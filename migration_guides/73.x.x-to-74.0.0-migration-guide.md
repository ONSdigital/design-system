# Migration Guide from version 73.x.x to 74.0.0

This document outlines the steps needed to migrate to version 74.0.0 of our Design System library from the latest 73.x.x version.

This major release focusses on our improving our Layout component (the base page template provided by the Design System) along with our Breadcrumbs and Hero components, and contains breaking changes that are likely to impact any projects that use them.

It also contains changes to the width of textual elements in wide mode and full-width mode, ensuring that text does not exceed a comfortable reading width.

Please follow this guide to ensure a smooth transition.

## Layout component (base page template)

### Markup changes to improve accessibility and semantics

See [**Improve landmark semantics in Layout component**](https://github.com/ONSdigital/design-system/pull/3824) and [**related pull requests**](https://github.com/ONSdigital/design-system/pull/3876).

-   The `<main>` tag has been moved higher up the HTML tree to ensure that all content is rendered inside a _landmark_ element ([W3.org reference](https://www.w3.org/WAI/WCAG21/Techniques/aria/ARIA11.html)).

-   The breadcrumbs have been moved so that they render inside the `<header>` to improve semantics.

-   The `<preMain>` block has been moved so that it still renders before the `<main>` tag.

-   The `main` block has been renamed to `mainContent`.

-   New `breadcrumbs`, `preBreadcrumbs`, `hero`, `postHero` and `postMainContent` blocks.

-   Instructions have been added for any blocks that are rendered outside of an existing landmark to explain that they must use a landmark level element.

#### Migration steps for renaming the `main` block to `mainContent`

1. Locate everywhere in your codebase you override the `main` block.
2. Update this to `mainContent`.

    ```nunjucks
    OLD

    {% block main %}

    NEW

    {% block mainContent %}
    ```

#### Migration steps for the `preMain` block

1. Locate everywhere in your codebase that you override the `preMain` block.
2. Ensure it is using a base element with a [landmark-level role](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Reference/Roles/landmark_role).
3. If necessary, add container classes, as it is no longer rendered inside an element with the container classes set.

    ```nunjucks
    OLD

    {% block preMain %}
    <div>...</div>
    {% endblock %}

    NEW
    {% block preMain %}
    <section class="ons-container">...</section>
    {% endblock %}
    ```

#### Migration steps for `Breadcrumbs` and `Hero`

1. Locate everywhere in your code base that you override the breadcrumbs and / or add a hero.
2. Move them to their individual blocks.

    ```nunjucks
    OLD

    {{

    <main id="main-content">

                "button": {
                    "url": '#0',

        ...Other page content

    {% endblock%}

    NEW

    {% block breadcrumbs %}

            "ariaLabel": 'Breadcrumbs',
            "variant": "pale-blue",
            "itemsList": [
                {
                    "url": '/',

                {
                    "url": '/',

                {
                    "url": '/',
    ```

## Breadcrumbs component

### New `fullWidth` and `wide` parameters

Included in [**Improve landmark semantics in Layout component**](https://github.com/ONSdigital/design-system/pull/3824).

-   **Description of change:** The breadcrumbs have two extra parameters: `fullWidth` and `wide`.
-   **Reason for change:** The breadcrumbs were previously rendered inside a `div` with the `ons-container` class in the base template, which already had the correct width options applied. Now that they are rendered inside the `<header>` they must set their own `ons-container` class, so need to have these options passed down to ensure their overall width is correct, via the `ons-container--wide` and `ons-container--full-width` classes.

#### Migration steps

1. Locate everywhere in your codebase where you override the breadcrumbs.
2. If you are using either `wide` or `fullWidth` in your `pageConfig`, update the breadcrumbs to match.

    ```nunjucks
    OLD example for sites where `wide` is set to true in the `pageConfig`. No customisation of the breadcrumbs override necessary.

    {{
        onsBreadcrumbs({
            "ariaLabel": 'Breadcrumbs',
            "variant": "pale-blue",
            "itemsList": [
                {
                    "url": '/',
                    "text": 'Home'
                },
                {
                    "url": '/',
                    "text": 'Business, industry and trade'
                },
                {
                    "url": '/',
                    "text": 'Retail industry'
                }
            ]
        })
    }}

    NEW example for sites where `wide` is set to true in the `pageConfig`. Breadcrumbs override updated to match.

    {{
        onsBreadcrumbs({
            "wide": true,
            "ariaLabel": 'Breadcrumbs',
            "variant": "pale-blue",
            "itemsList": [
                {
                    "url": '/',
                    "text": 'Home'
                },
                {
                    "url": '/',
                    "text": 'Business, industry and trade'
                },
                {
                    "url": '/',
                    "text": 'Retail industry'
                }
            ]
        })
    }}
    ```

[**See full example**](src/components/breadcrumbs/example-breadcrumbs-wide.njk)

## Restricted reading width for text - wide mode and full-width mode only

### New utility classes and automatic restrictions

A new utility class, `ons-u-reading-width` has been added to ensure that consumers can restrict the maximum reading width for ad hoc elements

The following tags are restricted by default, regardless of class: `<p>`, `<h2>`, `<h3>`,
`<h4>`, `<h5>`, `<h6>`

A new utility class, `ons-u-no-reading-width` has been added in case you need to remove the reading width restriction for one of these elements.

`onsPanel`, `onsAccordion` and `onsDetails` components will automatically apply restrictions to lists, lables and legends within their child content.

The following components have been updated to apply the restriction to their textual elements:

-   onsAddressInput
-   onsAddressOutput
-   onsAutosuggest
-   onsBackToTop
-   onsCharLimit
-   onsDetails
-   onsFeaturedArticle
-   onsFeedback
-   onsFigure
-   onsInput
-   onsLabel
-   onsList (but not for inline lists)
-   onsMessageList
-   onsPanel
-   onsQuote
-   onsSkipToContent

### Migration steps for onsPanel, onsAccordion and onsDetails

-   Locate any text within these components that is inside a `<div>`,`<a>`, `<span>` or other element not listed above
-   _Either_ wrap it in a paragraph tag
-   _Or_ apply the utility class to the tag, making sure it is using a block level display

These steps will ensure the text does not exceed the maximum reading width.

### Migration steps for ad hoc elements

-   Locate any content in your application that is using ad hoc markup, rather than calling a design system component
-   Find any text that is not inside a paragraph tag or a heading tag
-   Apply the `ons-u-reading-width` class to the tag, making sure it is using a block level display

## Migration steps for any paragraph and heading text that should not be restricted

-   Locate any text within `<p>` tags or `<h2>` to `<h6>` tags that should not be restricted
-   Apply the `ons-u-no-reading-width` class to the tag
